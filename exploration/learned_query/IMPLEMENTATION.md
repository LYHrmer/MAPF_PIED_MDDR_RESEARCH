# 首版原型：实现与验证

日期：2026-09-24。状态：可运行的独立软件原型，不是原系统集成或科研性能结果。

## 已实现

- `model.py`：标准库实现的逻辑回归，训练集独立标准化、按完整运行分组划分、概率及 Brier/log-loss 描述指标、模型参数序列化。
- `shadow.py`：不可变有理快照、合法历史与报价的选择、割线基线、概率期望 A/P 评分、查询建议及条件标签构造。输出仅为建议，空排名交还原调度器，不自建轮询游标或发布权限。
- `example.py`：明确人工构造的标签、训练和留出运行、两候选影子排序，输出 JSON。无需安装第三方库。
- `decision_structure.py`：小型固定依赖图的精确有理数决策诊断，比较软 A/P 字典序与自适应两步前瞻；不调用机器人仿真。
- `decision_ablation.py`：固定真实分布，分开预测估计与策略评估的四格诊断。人为粗估和准确概率都不是新训练的模型。[解析结果](DECISION_ABLATION.md)展示预测改善、组合决策改善和反例控制。
- 四份 `test_*.py`：模型约束、信息时序、严格边界、AND 阻塞、端到端组合与已知解析反例检查。

模型的六个输入按顺序为预计下界增益/剩余授权跨度、查询精度/跨度、采样信息年龄的 log1p、预计捕获等待的 log1p、是否有两次历史捕获、阈值距认证进度/跨度。只有最后一项随同一查询的阈值变化。

逻辑回归采用训练集均值和正标准差缩放；最后一维系数投影为非正，因此通过 `fit` 得到的模型对固定查询上下文给出随阈值不增的概率。该性质不等于校准保证。这里没有图模型、完整世界模型或强化学习。

## 标签与评分的准确含义

首版学习的是**给定返回合法且匹配的证书时，该证书下界严格越过选择时阈值的概率**。它不预测实际位置，也不预测“在某个截止前得到有效返回”的联合概率。无效、未完成和未查询记录返回缺失标签，不能填为零；若不同候选的失败风险不同，当前条件概率评分可能偏向低可靠来源，该问题尚未建模。

同一次查询在多个阈值上产生的标签共享 query ID；训练/测试按完整 run ID 划分。该工具不自动证明跨地图独立，不修正行为策略造成的选择偏差。示例三个运行组实际重复相同的 16 组人工特征/标签，仅改变运行 ID，只检查数据和代码链路，不代表独立测试或跨场景泛化。现有损失按标签行平均；代表性数据引入前需确定同次查询多阈值的权重，不能通过增加容易阈值改善指标。

`expected_admissions` 是当前冻结依赖视图下、条件于有效返回的加权预计准入量；它不预测后续图变化或全窗口任务完成量。部分收益仍保留全部 owner 数，包括不可查询/不可退休的阻塞者。费用时间乘积仍是启发式分母，不是已证明的最优目标。

## 如何运行

在仓库根目录执行（Python 3.10 或更新版本）：

```bash
rtk proxy python3 -B -m unittest exploration.learned_query.test_model exploration.learned_query.test_shadow exploration.learned_query.test_integration exploration.learned_query.test_decision_structure -v
rtk proxy python3 -B -m exploration.learned_query.example
rtk proxy python3 -B -m exploration.learned_query.decision_structure
rtk proxy python3 -B -m exploration.learned_query.decision_ablation
```

2026-09-24 实际运行：33 项联合测试通过；原有两份示例及新增四格诊断均 exit 0。覆盖训练标准化隔离、阈值概率单调、捕获前后等待区分、未来信息隔离、最新零历时报价不能回用旧报价、严格大于阈值、完整 owner 集、缺失标签和响应身份、只读建议、源费用非负及未来需求拒绝；新增检查覆盖评估时第二步也不能使用真实概率重选，以及估计零概率事件后的继续决策。

示例使用两个训练运行组及一个留出运行组；留出组为 4 次人工查询、16 条相关的阈值标签。割线基线建议 `fast`，学习评分排序为 `fast, slow`；两者首选相同，不能据此宣称学习更优。输出中的拟合/排序秒数只是本机墙钟诊断，没有映射到 B1，也不能作为机器人查询延迟或净吞吐证据。没有生成研究结果文件。

新增精确机制诊断发现：在两需求均须 A、B 两份证据、另一需求只须 C 的冻结图上，令跨阈值概率为 `1, 1, 1/1000`；每次返回均有效，每对象至多查询一次，查询成本/延迟相同，预算为两次，期间无外生需求或依赖变化、额外冲突或自动释放，成功证据仍删除已满足关系。软字典序必先查 C，期望准入量 `1/1000`；两步前瞻先 A 后 B，期望准入量 `2`。程序用 Fraction 穷举结果，未进行随机仿真。代码也检查不确定 A/B 下第二次查询随结果调整、单步单owner场景中不虚构前瞻收益，以及预算增至三次后两方法均为 `2+1/1000`。

该反例说明即使概率准确，字典序目标仍可能错过 AND 互补收益；它不证明原系统已出现该情形，也不建立吞吐改进或真实系统上界。现有 `shadow.rank` 保留为对照，未悄悄改成新调度策略。两步程序只是冻结图比较器，尚未接入概率模型或实际执行。

本程序针对 soft A/P；主线二值规则若把 C 预测为不跨阈值，不会出现同样的 ε 级差距。`p_C=1` 子例则显示抽象确定性字典序的 1 对 2。后续已将真实概率与策略估计分离，可作人为预测质量诊断，但仍不等于学习性能；全零分数按名称选择，也未复刻原系统的 RR 回退。当前证据只支持进一步核查组合查询在受限预算和真实状态演化中的作用。

## 与现有 C++ 的接线状态

本轮只读核了主线 `implementation/pie_query/include/` 中的 scheduler/index 接口。没有复制其依赖或修改主线：

| 原型需要的内容 | 现有接口与缺口 |
| --- | --- |
| 动作 q/b、MOVE 身份、需求及完整 owner 关系、阈值/退休资格 | `Scheduler::structure()` 可读；一跳权重可由 requester/out 派生。 |
| 两次合法历史及最新兼容收据 | `Evidence`/`Receipt` 和输入 Delta 公开，但已保留的 histories/receipts 私有，缺少完整只读快照导出。 |
| 全候选评分 | `choose` 只返回获选者的 Score，不能由它重建全部候选的历史、报价和状态。 |
| 精确数域及费用 | 原系统有实代数数与 B1 计费；当前只有合成 Fraction 快照和宿主诊断。 |

下一接缝是只读导出最外层成功提交后的状态，或镜像该发布点确认的已准入 Delta 流。不能把内部 `Scheduler::commit` 当成导出触发点，因为外层 prepare 也会调用它组成私有候选。不能读取 prepare 的私有后继、模拟器真值或未来扰动。真实代数边界不能简单转浮点后声称仍是原精确判断。具体字段、最小接线及来源见[数据接口契约](DATA_INTERFACE.md)。

本原型信任调用者给出的 `valid/settled/retirable/other_ready` 标志，不自行验证来源或几何。尚无实际导出器、真实日志回放、B1 对应、模型失效后的在线接管或系统级收益检验。代码不能当安全控制器使用。
