本结果支持“这种组合结构在共同几何与运动约束下能够出现”。两次查询后的数字是需求可准入数，并进一步通过组件的 admitted-update 路径安装了对应新动作；没有执行 AUTH/CenterService、完整费用链或任务完成服务，不是吞吐或学习收益。

## 空间和初值

同一空间由 90 个闭方格覆盖：方格中心 x 为 −3 至 11、y 为 −1 至 4，每格边长 1。覆盖范围为 [−7/2,23/2] × [−3/2,9/2]，包含所有原 MOVE 的完整足迹扫掠和误差扩张。所有机器人使用相同、固定世界朝向的实心方形足迹 [−1/10,1/10]²，误差盒为 [−1/20,1/20]²；横向误差非零。没有点机器人、空误差盒、旋转、换原 MOVE 或几何绑定替换。责任计算始终覆盖整个误差盒。

实际运行的 ReferenceController 只提供标量参考进度见证，程序没有积分二维扰动 z。可选择盒内合法误差轨迹 z=0，将该进度嵌入表中固定直线 MOVE，得到与全部责任包络相容的空间轨迹；这证明一个存在性的可达见证，不是已运行二维扰动鲁棒性试验。

| 身份 | 原 MOVE 起点 → 终点 | 原长度 | 初始角色 |
| --- | --- | ---: | --- |
| A | (0,0) → (0,3) | 3 | 先驻留，再授予原 MOVE 全 cap |
| B | (2,0) → (2,3) | 3 | 同上 |
| C | (8,0) → (8,3) | 3 | 同上，与 A/B 区域分开 |
| D1 | (−2,1) → (4,1) | 6 | 保持起点驻留，等待初始 start 需求 |
| D2 | (−2,2) → (4,2) | 6 | 同上 |
| D3 | (6,1) → (10,1) | 4 | 同上，只受 C 阻塞 |

夹具先由各自 `Geometry::n_mask(0,0)` 建立六份驻留责任，逐一检查资源无重复。再分别计算 A/B/C 的整个原 MOVE `n_mask(0,ell)`：仅当其中每个资源为空或为该机器人自己的驻留责任时，才通过 `PositionCommit::prepare_admitted_update` 安装动作、完整 cap 与几何 owner。这明确检查了 D1/D2/D3 的等待起点与 A/B/C 全过程责任不重叠，也避免让 A/B 起点或运动包络互相占用。

随后 D1/D2/D3 以各自完整 MOVE 的 `n_mask(0,ell)` 登记请求，`requester_action` 为空，符合 Index 的初始请求形式；尚未安装它们的活动 MOVE 或 cap。`non_owner_eligible=true` 明确预设其他准入条件已经满足：这些人工机器人已在给定起点静止、提出给定合法几何的下一动作。夹具没有验证规划器、服务或 AUTH 资格；没有合成 CAP_EXTEND 或调用一个总返回 true 的扩展判定器。结果是这些前提下的空间合法 AND 见证，不是生产系统所有条件通过。

原生 admitted-update 接口接受的是已准入输入。上述资源检查证明该输入满足本夹具的资源前提，**不认证输入来源，也不替代生产 AUTH、行机会、任务及生命周期 guard**。

## 真实 owner 和严格阈值

所有关系从真实 Index 输出逐条读取；运行 JSON 的 `initial_relations` 不是手写期望列表。

| 需求 | 实际关系 owner | 每个 owner 的实际退出阈值 |
| --- | --- | --- |
| D1 | A、B | 33/20 |
| D2 | A、B | 53/20 |
| D3 | C | 33/20 |

例如交叉行 y=1 的格子上界为 3/2，加足迹半宽 1/10 与误差半宽 1/20，得到退出位置 33/20；y=2 同理为 53/20。这个手算仅解释输出，代码另从真实区间 `extract` 复核 Index 阈值。闭集相交要求证书下界**严格大于**阈值才退休。

两个独立控制检查分别在真实控制器达到 s=33/20 与 s=53/20 的精确时刻提交证书。等于阈值时对应 A 关系仍在；B 查询成功后，D2 仍因处于等号的 A 而被阻塞。A 随后严格越界才清除。每次 POSITION 都核对增量退休后的 mask 与直接 `n_mask(q,b)` 一致。

查询后始终检查原终点 `n_mask(ell,ell)` 中每个资源仍由原动作持有。另在控制器到达 s=ell、v=0 并关闭时运行一个终点组件控制：中心尚未处理外层 END，POSITION 只能缩到终点资源，不能清空原终点责任。该控制不声称完成了合法生产 END 链。

## 同一可达轨迹与两次机会

使用现有 ReferenceController 数学测试的人工系数 δ=1、a_lo=2、a_hi=6、a_launch=1、η=−1，原长度与本地已安装 cap 均为 3。它们仅属于这个具名数值夹具，未写入研究配置，不表示经过验证的机器人能力，也没有赋 H、Tdelay、B* 或 density。

每条顺序都重新创建相同初值的全部三个控制器，t=0 从静止 RUN。真实组件给出：t≤2 时 s=t²/2；2≤t≤3 时 s=3−(3−t)²。固定两次机会为 t=5/2、11/4，三个机器人的真实进度分别都为 11/4、47/16，均在同一个原 MOVE 内且尚未到终点。所有控制器每次都共同推进；交换查询顺序不改变轨迹或扰动。

证书是明确标注 `artificial-native-not-AUTH` 的 admitted-source 替身，下界取所查询控制器快照的精确 s（对应区间 [s,s]，宽度 0，不超过声明精度 1/10），绑定相同原 MOVE、几何、cap 和捕获时刻。它不是经认证的生产源。两次机会的捕获、交付、提交时刻在这个有限夹具中重合；不表示研究通信延迟为零，也不模拟其成本。

每次只把被查询者的证书交给 PositionCommit。另逐个断言：未查询者即使已经运动也保持 q=0；只查询过一次者的 q 停在第一次下界。私有运动只用于隔离的可达性断言和人工证书构造，没有进入调度器/学习模型。

| 查询顺序 | 第一次后可准入数 | 第二次后可准入数 | 随后组件安装的新动作数 |
| --- | ---: | ---: | ---: |
| A → B | 0 | 2 | 2 |
| B → A | 0 | 2 | 2 |
| A → C | 0 | 1 | 1 |
| B → C | 0 | 1 | 1 |
| C → A | 1 | 1 | 1 |
| C → B | 1 | 1 | 1 |

每次可准入判断同时核对 Index 的空关系和真实 owner 表无外国责任。第二次后对所有 ready 需求再次检查完整扫掠 mask，再通过 PositionCommit 的 admitted-update 安装动作、资源所有权并移除请求。A→B/B→A 中 D1 和 D2 可以依次安装，未因第一项新授权造成第二项冲突。请求者控制器和任务服务没有运行。

这里是手工列举六种查询顺序，查询结果均成功，预算只是给定两个有限机会。没有运行原 SRDC、COUNT、RR 或学习排序器；没有复现此前 C=1/1000 的随机图，也没有推断原启发式会选择哪条顺序。它证明组合查询结构及有限机会下的顺序差异，不证明新策略更优、实例常见或长期吞吐改善。
