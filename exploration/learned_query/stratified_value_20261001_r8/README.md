# R8 stratified query value study

This package extends the frozen R7 frontier adapter with new whole-run data, public opportunity stratification, task-primary advantage targets, weighted standardized ridge models, and fixed public-time query pacing. It preserves the pinned official OnlineGGO OBJ3 planner and the original exact physical/query stack. See `CONTRACT.md` for the pre-outcome specification and `REPORT.md` for results and limits.

The actor sees current public commitments, current FIFO heads, normal-END history and its own query budget. A selected POSITION query is the only source of current physical progress. Future FIFO goals, hidden error signs, physical offline frames and evaluator labels are not actor features. No author planning baseline is replaced with a custom search algorithm; the comparison policies are explicitly internal query rules.

`REGISTRATION.json` freezes all18 worlds and method sources before native training/calibration execution. `LABEL_SELECTION_BEFORE_PROBES.json` freezes all selected opportunities before their interventions. `TRAIN_CAL_LABELS.json` retains every selected candidate; no zero, negative or failed outcome is removed by an outcome-based selection rule. `MODELS_FROZEN_BEFORE_TEST.json` holds both actual fitted models before the original60 held-out/scale attempts and the12 compatibility reruns. WAIT has exact zero advantage by definition; candidate intercepts are not mistaken for a WAIT feature prediction.

The original12 N32 attempts were rejected by an inherited N<=16 constructor guard before any physical execution. All failures and original code remain. `scale_guard_successor/` records the post-outcome compatibility fix: exactly one native token changes the constructor limit16 to32, and all12 original inputs/models are rerun unchanged. These are the same two scale families, not additional independent test data. `RESULTS.csv` distinguishes original and successor generations.

Primary evaluation is whole-run completed FIFO tasks by H128. Restricted completion-time sums for the same initial first4 tasks per agent are secondary; query counts, resource releases and reduced fixed-prefix time do not compensate for fewer tasks. Four N16 task families under paired IID/SHIFT and two N32 scale families do not establish population significance or cross-map generalization beyond these two tested maps.

To inspect archived traces, extract `RAW_R8_TRAIN_CAL.tar.gz` and `RAW_R8_TEST_SCALE.tar.gz` in this directory. `RAW_ARCHIVE_MANIFEST.json` records every input, raw/planner trace, receipt and stderr digest. Raw traces are archived once; expanded `runs/`, audit caches, binaries and Python caches are excluded from the publication list. External dependencies remain pinned local paths in `runner.py`, and the package is not self-contained on another machine.

To rerun the complete study, copy source files, contracts and the successor source directory into a fresh sibling directory under `exploration/learned_query/`, retaining the existing parent legal fixture and pinned external dependencies. Run the copy's `pipeline.py`, then `scale_guard_successor/run.py`; this intentionally reproduces and retains the original guard failures before the corrected scale runs. Do not rerun against this frozen result directory: evidence files use exclusive creation. Run both `audit_all.py` files, plus `verify_model_labels.py`, `negative_controls.py`, `tail_diagnostics.py` and `summarize.py` on the fresh output. The root-independent held-out checkers are separate from the implementation pipeline.

Training labels assume one current query followed by WAIT. Deployment can issue up to16 adaptive queries, so the learned target omits the effects of later queries and future budget opportunity costs. The training/calibration sample contains no negative task-advantage labels; this is not evidence that queries are harmless. The held-out report and tail diagnostics retain task losses.

The900-second runner elapsed-time guard is checked between received native lines; it is not a hard interrupt of a blocked `readline`. Actual per-episode elapsed times and failures are retained. Concurrency changes are scheduling decisions, not measured production COST or physical-speed claims.
