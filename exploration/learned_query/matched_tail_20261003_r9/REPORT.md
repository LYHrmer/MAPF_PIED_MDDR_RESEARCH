# R9：相同续策边际查询价值与单次策略替换

R9修正了R8的监督续策失配，但没有发现新增学习收益。八个新N16留出world中，固定condition及history/nohistory/nobudget三个单次替换策略均完成367项任务，查询均为123次，固定first4受限完成时间也完全相同。WAIT完成366项。相对WAIT的1项总差来自原condition，不能归因于学习、历史特征或预算因子。

本轮完成91个原生运行：6个condition数据收集基线、45个完整反事实分支、40个留出测试臂。全部到达H128，无执行失败、无死锁；没有因结果追加样本或调整阈值。训练、测试、分析和证据重放均已实作完成。

## 目标与部署为何现在一致

固定未分时公开condition为pi0。先完整运行pi0，从其真实到达状态按预先登记规则选择机会；每个机会逐一运行当前WAIT一次和全部合法query，之后均恢复同一个活的condition。保留原END历史及剩余预算，不重置策略，不约束分支之后的候选集。WAIT返回原事件循环，必须到下一个原生决策事件才允许查询；query实际扣1单位预算。完整前缀逐事件一致性包含此前动作、历史、资源、物理状态及预算。

标签为`A(a)=J(a→pi0)-J(当前WAIT一次→pi0)`。J以全run完成任务数为首项，再减去每agent初始first4 FIFO任务的受限完成时间和除以16385。未完成固定任务计H128；完成时间取1e-6分辨率日志区间中点，原区间保留，主任务计数为整数。该次项不能反转一项任务的主指标差异。WAIT有显式续跑结果及精确零优势，但不生成伪造零特征训练行。

测试策略只在“已用至少6预算、仍有预算的首个非空机会”以模型替换一次pi0决策，然后永久恢复pi0。这与标签定义的单次干预具有相同尾策略；没有把旧标签用于反复部署一个新策略。所有臂容量均16，整程WAIT实际消耗0；查询次数没有换算为生产COST或任务收益。

## 数据、模型与预先固定的范围

两张公开MovingAI地图为empty-32-32和random-32-32-10。每图2个新训练run、1个校准run、2个新测试family；每测试family配对IID/SHIFT，SHIFT在各agent实际MOVE ordinal64后翻转私有误差符号。训练、校准、测试scenario行组及任务ID按完整run划分。地图和所有seed、任务储备、超参数、机会规则都在运行前登记。

在已用预算0..5、6..11、12..15三层中分别取首个单候选、首个多候选机会，每run最多14个完整分支；选中机会必须保留WAIT及全部候选。实际得到21个机会，其中3个多候选；执行24个query分支和21个WAIT分支，共45probe，低于84上限。未达到上限没有触发补采样。训练为4run/14机会/16query标签，校准为2run/7机会/8query标签；同run和同机会内的行不独立。

保留原20个公开特征，新增剩余预算比例、公开时间比例，以及两个明确的预算交互项。三模型均为24维ridge，固定lambda1、截距不惩罚、每机会总权重1。训练数据独立计算均值/尺度；nohistory在预处理前屏蔽10..17，nobudget在预处理前屏蔽20/22/23，线上同样屏蔽。nobudget保留合法公开时间和历史，它们可与预算相关；这不是消除所有统计相关性的实验。消融仅作用于替换时的模型，前缀和续策始终是同一个有正常END历史的condition。

模型折回25个原特征系数并舍入1e-9，原生使用精确有理评分。固定WAIT得分0，模型仅在最佳query得分严格大于0时查询。校准不选择lambda、阈值或模型。模型冻结SHA为`ec96643b3b4bc8d81b26731c983ed05b4578b5595a13aad59456ceff596a1f76`；冻结收据记录当时0个test receipt，全部40测试输入与该系数集合一致。

训练16标签为3正、8零、5负，**全任务数差全部为0**；非零训练信号仅来自固定FIFO次项。校准8标签为0正、5零、3负，其中empty91201机会1的query→condition完成47项，WAIT一次→condition完成48项，两支最终都用16次query。它是预算续策下查询可能有害的实测反例，不是执行失败。

history/nohistory/nobudget的校准加权RMSE分别为0.378732、0.378849、0.378701。校准7机会中，前两模型全部选到并列最优；nobudget为6/7，差异只涉及时间次项。没有据此修改模型。训练缺少任何主任务差异的样本，不能因回归完成就声称已学到吞吐价值。

## 模型确实改了什么

三模型各在8/8world触发一次评分。history和nohistory各4/8实际改变原condition动作，nobudget为6/8，合计14/24次；这些改变全部是query改为当前WAIT。它们发生后均在下一个原生事件继续pi0，没有同刻补查询。

但24次触发全部只有1个候选，因此本轮留出仅检验query/WAIT门控，**没有检验留出多源排序**。所有触发均发生在任何ordinal64 MOVE启动之前，所以SHIFT只扰动后续执行；**不能称为漂移发生后的历史适应**。这些限制来自预定规则的实际覆盖，没有事后更换触发机会。

14次实际动作变化没有带来任何一个world的主任务数、固定first4时间和总query变化。逐事件诊断还显示，14支的全部任务服务记录和planner请求与condition相同，原RUN和物理END记录则全部发生变化；其中8次被跳过的原query未实际释放source资源，另外6次会释放资源。因而这不是完全没有物理影响，而是本轮影响没有传递到任务服务。对应精确候选分数、变更率及诊断见TEST_REPLACEMENT_DECISIONS.json和REPLACEMENT_MECHANISM_DIAGNOSTICS.json。
