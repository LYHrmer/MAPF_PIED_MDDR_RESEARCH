# R11 科研导师独立后评

本轮最扎实的正结果是主线在相同行为下减少了真实执行费用；第三线补齐了作者图到共同事件几何层的有限接口；查询线发现了可复核的服务时间改进，但尚无任何登记干预在任务数上同时超过 condition 和整程 WAIT。三者支持继续有边界的研究，尚不支持把一个新的学习模型列为论文核心贡献。

本评估按 research-mentor 单独组织判断，与 Astra 评估分别成文。第三线实现由本角色完成，物理几何与关键事件由 root 另写审计器核验；这里不冒称盲审或独立重复实验。使用的是隔离探索工件，未改主稿，未改变冻结的 R10/R10b。

## 主线：本轮最实质的系统结果

[主线报告](/home/lyh/MAPF_PIED_MDDR_RESEARCH/implementation_binding_evidence/incremental_lifecycle_20261003_r11/REPORT.md)和 root 独立 `ROOT_COMPARE.json` 支持以下判断：六种输入各跑 Natural/Strict，仍为原 16 tick、4 项任务；1388 条非费用、非宿主耗时事件与 R10 对应相等。Natural actual 减少 **11.63%–21.14%**，Strict charged 减少 **1.36%–2.54%**。后者按实际开段收费，不能用前者的降幅代替。所有新比较、保留、分配与析构都在实际 guest 中付费，因此不是把优化开销移出账本得到的下降。

关键机制是已付费历史的合法复用：本次仍读取全部真实输入，确认稳定身份、种子和完整旧命令前缀相同，再调用原控制器推进新后缀；失配和 occurrence 换头则销毁缓存、全量重建。原控制器数学未被近似替换。这是可解释、可审查的实现优化。不过完整历史读取和前缀比较仍随历史增长，缓存字节也随历史增长，不能宣称端到端渐近复杂度改善或常量空间。峰值 guest 字节尚未测量；原 workload 之外的稳定收益也未建立。缓存本身是常见技术，其论文价值应来自清晰的有偿核验合同、正确性和可复现的费用效果，而不是单独以“增量”命名作为创新证明。

查询价值边界没有因这次优化而改变。长例仍是 WAIT/paid 都完成 4 项、服务时刻和 50→44；R11 为此增加 118,894,306 个 Natural 实际工作步。短/中例没有服务时刻优势。生命周期验证器仍能为正常 END 核验读取未闭合 history，决策器是否可以使用、什么证据可以授权提前释放是另一个合同。因此目前支持额外认证的合法提前放行，不支持“WAIT 对物理进度一无所知”的叙事。运动时间与工作步没有预先定义兑换关系，不能称长例已经取得综合净收益。

## 查询：主要任务空间仍弱，但真实时间收益不能抹掉

[查询报告](/home/lyh/MAPF_PIED_MDDR_LEARNING_EXPLORE/exploration/learned_query/public_opportunity_20261003_r11/REPORT.md)记录 94 次真实执行：8 个整程参考、26 个单干预分支、60 个固定双干预策略，零执行失败；94 份原物理/精确策略审计已通过。`MATCHED_TAIL_AUDIT.json` 对 94 条运行的前缀/尾策略核验通过，含 38 个同动作或第二次干预未触发时的完整轨迹控制；58 条 SKIP 生命周期核验和 22 项拒绝负控也通过。root 不导入候选实现，另从 94 份原始运行复算价值、分支选择、谱系与实际触发，`ROOT_VALUE_SPACE.json` 为 PASS。它们都是 TRAIN 机制诊断，没有训练模型，也不是留出测试。

empty111101 有一次机会允许相对原 condition 增加 1 项任务，但整程 WAIT 已有 49 项。因此 R10 的“原 π₀ 主项空间全为零”不能直接照搬到 R11；同时，这个新正标签仍没有超过双参考。所有 60 个双干预相对同首动作的单干预都没有任务数正增益，一臂反而少 2 项。这个有限结果不足以支持马上扩大吞吐价值模型，也不是全策略最优性证明。

还要保留策略选择的积极空间：condition 和整程 WAIT 各自跨四族都合计 188 项，逐族最佳登记结果合计 189，恰等于逐族取两个参考较高者的包络。因此“没有超过逐族双参考包络”不等于“选择策略没有学习潜力”。189 是 TRAIN 中看完结果才知道的逐族选择，不是一个已冻结、能从公开信息识别应选哪条策略的部署模型。后续若研究整程策略选择，需要把它与当前单机会动作价值分开定义、比较并留出验证。

时间次项存在实质、精确区间支持的信号。登记目标为 `J = tasks − T/16385`，T 是固定每 agent 前四项任务的限制完成时间和，未完成记 H=128。**11 个干预臂的 J 同时稳健超过两个参考，分布在 2/4 family**：empty111101 四臂、random112101 七臂。这些是相关分支，不能当 11 个独立样本。random112101 一例 `pair_9_SKIP5_SKIP_distinct` 保持 48 项任务，T 相对 condition 减少区间为 [6.988960, 6.989052]，相对整程 WAIT 为 [20.621247, 20.621339]；这是正的服务时间差，不是区间中点的舍入假象。但这 11 臂都花了 16 次 QUERY，而整程 WAIT 是 0，尚不能由此声称真实计算费用后的净收益。

empty111101 的最佳登记双干预同样保持 WAIT 的 49 项任务，T 还能相对 WAIT 减少 [1.268228, 1.268320]。因此“任务数没有同时超过双参考”不能被改写为“次项也没有超过双参考”。这两族的正时间信号和另外两族的限制应同时保留。

不同 occurrence 的第二干预 48/48 可达，其中 5 臂的 J 优于对应同首动作单干预；公开 successor trigger 只在 5/12 臂可达，其余 7 臂保留为未触发，不能记成成功选择 WAIT。后者的第二干预既无任务正增益，也无稳健 J 正增益。下一研究目标若明确改为“保持主要任务、减少固定 FIFO 服务时间”，已有可用的局部机制信号；若仍称“提高吞吐”，目前数据机会不足，不能只怪模型弱。两种目标不能在结果出来后混用。

## 查询 coupled 缺失是有条件的结构判断

这次 condition 选出 8 个机会，只有 1 个含两个候选，coupled 为 0。完整 94 轨迹里仍有 180 次多候选决策、分布于 84 臂，coupled 依旧为 0；重复轨迹的这些计数不是额外独立覆盖。

[单独的源码推理](MENTOR_QUERY_STRUCTURE_20261003_R11.md)比“低密度没采到”更能解释这个现象。当前 footprint 为半宽 .1 的方形加半宽 .05 的误差盒；单位 cardinal sweep 仅覆盖起点与终点两格。请求者起点属于自身，Index 排除自身 owner，终点只有一个外部排他 owner，所以单请求至多一个外部关系。候选仅 source 可被查询退休；对该 source 的后续计划访问，又被唯一计划终点、`last_depart` 离开先序、真实 RUN 门槛和每 robot 一个 next 请求串行化。因此在这些条件下，同一候选至多一个当前 blocked-head claim。增加同规则下的 agent 密度，并不改变这两个不变量。

此结论只限当前即时 claim/foreign-owner 接口。它不排除两个独立候选需要排序，也不排除单阻塞沿后继任务和剩余预算产生非局部价值，更不否定其他图特征或一般学习。R11 的时间次项正结果正说明不能把结构退化外推为“所有干预均无价值”。若要研究真实多资源耦合，应以有实际任务依据的多 cell primitive、较大 footprint 或多个合法当前需求另立合同；不能删除安全依赖或提前暴露未来请求，只为得到正标签。

## 第三线：共同执行层过关，方法本身尚未形成

[第三线报告](gses_primitive_20261003_r11/REPORT.md)保留真实作者完整路径和原/采用图，43 项作者编译源未变。16 次单位格 MOVE、零 TURN/STATION 的退化执行逐时刻匹配作者轨迹，调度时没有把记录的未来状态当动作。其余 11 例加入转向、逐顶点驻留、方向减速或半程暂停。进入目的格在进度 .4，完整离开源格在 .6；半程 .5 不推进作者 state；type2 要等真实 ARRIVE，TURN/STATION 与完工后驻留均持有占用。

root 不导入候选 executor，独立审了 27 条完整运行、239,222 个 MOVE、523,274 条连续覆盖轨迹段和 72,636 对精确候选段。27 例全部通过。t=1/2 时包含 57 个在途 MOVE 的实际 JSON checkpoint 经恢复后，全事件/轨迹与不中断执行一致；九个本地破坏控制均拒绝，另有 root 的事件/几何负控。实际 GSES timeout 的原图回退也保持完整 trace 相同。

这些结果能支撑作者方法的共同执行接口与有限承诺守卫，不能写成新的连续控制器。MOVE 仍是分段线性几何，速度切换瞬时，没有接原反馈控制器；没有在线调用作者求解器后采用一张不同新图的完整闭环。几何核验也没有新增独立障碍物/动力学认证。所用作者输入是接口回归，不是 27 个新独立性能样本。

值得保留的反例是 random60：三种 primitive 配置中，GSES/Improved 采用图的完成时间和都低于原图，makespan 却都更高。旧作者目标下的解不天然支配新执行目标；下一次登记必须先指定主目标。之前 ridge 两轮负结果继续保留，当前没有理由把它恢复为核心方法，或者将预测的全部时长再作为通用拥堵罚项。

## 对下一合同的赞成、分歧与优先级

我赞成 [下一方法合同](NEXT_METHOD_CONTRACT_20261003_R11.md)把“实际在途采用不同合法图”放在训练模型之前；合同对自写适配器、原作者方法、同图恢复和不同图切换的区分准确。**我的近期工程排序是：有限的作者新图实际采用 → 明确各信息面与收费边界 → 再决定是否有必要引入原连续控制器/多资源接口和学习。**已有 checkpoint/占用证据使第一步成本有限，且能直接关闭“候选不能真正进入执行”的缺口。

这与 Astra 倾向先补多资源原控制器接口的排序有侧重差别。若论文核心仍锁定即时组合阻塞，那当前单位格接口没有相应结构，Astra 的前置接口要求更合适；但若近期问题是确认作者新图能合法用于当前执行，我不认为必须先完成完整控制器移植。两条工程顺序都不自动带来论文新颖性。主线费用结果继续作为可靠底座；查询吞吐学习暂不扩训，服务时间目标只有在明确改合同并保留吞吐约束后才值得继续。

对论文差异，我比“加一个任务价值模型”更谨慎。[REMAP/ESADG](https://arxiv.org/html/2511.21886v2)已把预测执行代价用于搜索和固定路径的 type2 次序优化，并以不确定性控制昂贵预测调用。[Should I Replan?](https://arxiv.org/html/2604.25567v1)已学习同场景单次重规划带来的实际 SOC 差。因此预测时长、学习完整后果差、添加图/历史特征或输出不确定性，都不足以单独成为区别。安全与已执行承诺也是执行式规划必须处理的约束，不能只换名当新颖性。

真正待验证的研究问题应具体到：**决策器在某个执行时刻缺少哪条合同允许获得的信息；获得该证据或生成候选究竟付什么费用；信息缺失怎样改变合法动作集合或动作价值；这种改变是否带来可重复的任务—时间—费用改善。**应先在相同候选、信息、求解预算和执行器下证明这个区别，再增加模型。若最后只剩更换预测器或给既有搜索换打分器，应如实判为近邻复现/工程扩展，不能靠命名补足方法贡献。

R11 没有必要继续扩实验找正数。当前三包已回答各自登记问题，后续必须新立协议；独立任务族、原始失败、不可达触发、负收益与次项收益都要保留。正式工作负载、真实外部对照、独立留出和空间/费用边界未完成前，不给 SCI 分区或录用概率承诺。
