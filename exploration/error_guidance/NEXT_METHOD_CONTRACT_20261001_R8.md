# R8之后的方法设计：从执行误差到有限预算下的任务收益

这是根据R8形成的**下一轮设计**，不是R8实验的事前注册，也不是已实现的方法。R8所有测试、模型和负结果冻结保留。具体新种子、场景数量、运行预算及模型超参数应在下一轮测试前另外登记。

## 1. 主线：把付费证据消费扩展成连续任务生命周期

当前已实现前车正常END的guest提交，以及END先于POSITION时的过期拒绝和完整结账。下一项功能应覆盖同一机器人连续两次MOVE、前后车都正常END、真实任务服务及下一任务头；分别检查旧action迟到证书、重复END、资源resident与新demand交接。不能将后车服务fixture的完成数直接充当在线LMAPF结果。

优先在现有绑定SOURCE、原控制器与统一计费合同下打通这个最小完整循环，再优化SOURCE读入。拟议的有界事件证据应含动作身份、状态版本及其与原执行历史的绑定，验证和维护也在guest费用中；单独一个host给出的closed标志不能替代证明。失败用显式拒绝结果传播，补掉当前异常诊断进入RV fault的路径。

这一层最终为各查询策略提供相同的证据、资源更新、正常END和费用接口。策略学习不修改安全准入。模型时间、guest工作计数、实际宿主时间三种量分别记录；没有硬件映射时不作兑换。

## 2. 查询线：学习相同后续策略下的预算价值

R8监督比较“一次查询后始终WAIT”与“始终WAIT”，部署却可继续查询16次。它估计的是特定单次干预收益，不能直接视为多次有预算策略的优势函数。下一方法必须同时表达剩余预算和后续行动。

令公开历史为h，剩余预算为b，合法行动为当前候选查询或WAIT。先固定可执行的后续策略π₀，对同一离线世界状态和同一外生误差序列，执行首行动a后双方都使用π₀，估计：

\[
A^{\pi_0}(h,b,a)=\mathbb E\{J_H(a\rightarrow\pi_0;b)-J_H(\mathrm{WAIT}\rightarrow\pi_0;b)\mid h\}.
\]

此处WAIT指当前机会不查询，随后仍执行π₀，并非整个余程不查询。查询分支扣除实际消耗的预算，等待分支保留预算；响应延迟、过期证书和后续合法候选集由执行系统自然产生，不在标签中假定查询必定成功。两个分支后续世界可以不同，不能为保持相同候选而改写真实执行。训练样本只输入h和b，离线真值仅用于运行反事实环境。

先以固定预算约束下的最终任务数为主目标，固定FIFO截尾完成时间为次目标，输出成对指标，不凭空把一条查询折算成若干任务。接入主线后，预算再由次数升级为已登记的guest费用；如果定义标量化权重，必须由部署要求或训练/校准阶段固定，并报告任务—费用曲线。

实施顺序：

1. 固定一个可复现的公开信息规则作为π₀和数据收集策略；按完整运行划分训练、校准和测试。公开时段、可见信息年龄、已交付END历史及候选数用于事前采样；所有候选及WAIT均保留。稀疏正标签不靠读取测试收益筛选。
2. 从π₀实际到达的状态复制离线分支，完成有相同后续π₀的成对rollout。保留零、正、负任务结果，以及无候选、过期和未完成状态。每个机会为一个统计单位，多候选不充当独立world。
3. 在同一接口先训练低成本价值排序模型，设显式WAIT行动。先只在事前选定机会替换一次π₀行动，随后回到π₀，以验证监督目标与部署完全一致；反复使用学习决策属于另一个策略，需逐轮重新采样和评价，不能宣称旧标签已估出新策略价值。对比同预算规则、无历史、去预算特征和旧单次WAIT-tail标签，区分预算目标改进与模型拟合改进。只用新训练运行做数据聚合，不回填旧测试。
4. 完全冻结后在新地图/新任务family配对。先检查主任务量，再检查固定FIFO时间、费用和失效机制。报告所有family的差值；IID和SHIFT共享family的结果不能当作独立重复。有限样本出现个别优势不写成总体改进。

费用预算下的证据分配是当前有区分度的研究假设；ridge、树模型或GNN只是实现选择。现阶段不需要视频世界模型。若监督排序确有任务收益、但长依赖的条件关系无法由简单特征表达，再以相同数据/预算比较图模型。

## 3. 误差引导线：先统一单步时间，再判断是否更换算法基线

R8两步缓冲内的合法局部执行已通，但批末仍有屏障；它不是无限异步重规划算法。原`getAvailableNodes`可提前将同机器人多个节点加入控制队列，因此不能假定admit之前自身前序已END。真实机械例中节点2在tick10入队，自身前序在tick36正常END，节点2在tick53结束；43tick队列驻留不能当作17tick单节点执行窗口。

下一轮对原parser的primitive节点定义P为公开提出时刻、R为原ADG扫描规则允许其入队的时刻（不包括附加global门和容量限制）、A为实际admit、E_prev为自身前序已接受的END、B=max(A,E_prev)、E为自身正常END。新时间分解为：

\[
E-P=(R-P)+(A-R)+(B-A)+(E-B).
\]

四项分别记录原依赖放行前的等待、额外门/容量调度等待、入队后的自身前序等待，以及前序关闭后的本节点完成时长。R必须另增与原扫描规则一致的公开事件，不能用事后私有位姿补写。首节点的前序约定、同tick事件顺序也需登记。新预测目标D=E−B仍含派发/权限暂停，不能称电机运动时间；原45+10turn整步名义时间不能直接套到半格MOVE或单独旋转primitive。

若仍采用整格动作而非primitive作监督单位，应另定义由哪些原节点合成，以及自身前序关闭时刻，不将两种尺度混用。第二步batch提出到END累计时间可作为整段完成目标，但不能再写入“单步执行时长”历史。仅减去前一步END也不必等于排除了全部跨机器人依赖等待。预测量与使用它的时刻必须一致；规划时尚未知的准入特征不得成为线上输入。具体源码与事件反例见[Astra技术后评](ASTRA_POSTEXEC_20261001_R8.md)。

重建数据后先检查同一公开事件集上分步预测和删失处理，再比较真实任务。固定原安全层与承诺前缀，优先让模型影响可改变的决策，例如有限窗口的候选路径代价或允许的通行顺序；模型预测更准但没有改变关键等待，不算方法收益。

若主张是改变执行顺序，下一作者基线优先[Improved GSES / STPG](https://github.com/DiligentPanda/STPG)；若主张是减少依赖同步，优先[P3GASUS作者图构造与执行](https://github.com/marmotlab/P3GASUS-graph-creation)。先运行作者最小例与正常基准，再统一输入地图、任务、误差、时限和信息。R8的global附加门继续只作内部消融，不能作为被击败的外部算法。对作者方法做任何接口改动需标注改动和重现偏差。

## 4. 论文结构与推进顺序

建议以“执行误差下，有成本的进度信息如何改善持续多机器人服务”作为主线问题；机制层负责证据消费和费用一致性，学习层负责在预算内选取有任务价值的证据。第三线为误差测量与执行接口提供验证，同时保留采用更适合学习的执行顺序基线的备选方向。不要把两种学习任务拼成互不关联的模块来增加工作量。

当前优先级为：主线连续动作/真实服务接口与查询预算价值标签并行，第三线同步修正单步监督语义。随后用冻结模型和作者方法做统一新测试，才决定哪项学习贡献进入正文。已发表基线、正式多地图多family实验和明确的新机制需要共同成立；增加训练量或网络复杂度本身不构成SCI二区/三区的创新证据。
