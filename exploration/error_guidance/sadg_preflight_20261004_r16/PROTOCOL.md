## 已确认机制及不变量

采用 R15 用户已接受方向，无需重复确认：在作者 `Vertex.get_progress()` 接入显式命名的 adapter，由合法公开历史或独立测量改变 `SADG.optimize()` 首个 IN_PROGRESS 动作的连续残余约束，检验未承诺依赖排序；不修改作者 MILP、ARRIVE、current 或 active commitment。

1. 原作者 checkout 文件不修改，源码 hash 与 import 来源可复核。
2. 原版、公开估计、测量估计始终用同一路径/分组/状态/时域/求解期限。
3. 所有 active 图边、type1、组方向、status 和完整解约束逐项核查，不抽样。
4. 只加载 Node 类型/标准 logger/输入，若需 shim 明示为无 ROS 核心 R0，不称全栈复现。
5. 解状态、可行解数、目标、gap、墙钟、原 60 s cap 全部归档；未知/不可行不采取。
6. POSITION 仅用于估计；模拟证据 production_cost=null，不伪造主线费用。

## 运行上限与去重

总计最多 12 个唯一作者优化输入。先 1–2 原生核心输入；余量用于固定静态小例的 stub、公开解析、公开历史、测量与残余边界，以及至多一个旧 checkpoint 的映射对照。每个调用保留作者固定 `max_seconds=60`，整个运行器另有外层 90 s 防挂起。按作者源码、adapter、全输入内容 hash 去重，不重复跑已成功输入。没有注册大规模实验。

合成例的进度范围、标称速度、历史估计和状态在运行前写入输入 JSON；不是付费生产证据。旧 checkpoint 只读取已归档 public、event prefix 和 measurement；不向求解器输入未来 heap/profile。若 compiler 或边界有 bug，记录原版失败，另写隔离 patch 版本，不覆盖作者库。
