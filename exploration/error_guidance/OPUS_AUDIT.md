# Claude Opus 定点设计审计

2026-09-24。根按用户允许调用 Opus 的要求，实际运行一次工具禁用的 Claude CLI
设计审计。CLI 完整返回 success，modelUsage 报告 `claude-opus-5`，历时
135370 ms，1 turn。输入为这项两路径、同观测策略的预检设计；Opus 没有阅读
最终夹具、执行程序或核验790项断言。实现与运行由 Astra Ultra 子智能体完成，
根阅读实际源码、核对回执与取舍意见。

采纳：把结论限定为给定误差盒、几何间隙、固定观测策略和原生准入前提下的
存在见证。两机器人均应用同组误差盒；四个组合都提交相同 t=4 观测。后继优先
检查观测时机与几何间隙/包络变化，再谈在线可学习性；现结果不支持替换 PIE-D。
实际组件验证与人工 AUTH/END 前提、模型时间与全部计算/通信费用分别报告。

根未采纳两条过强限制：

- 离线反事实不能作为训练标签：一般不成立。合法配对仿真的结果可以作为离线
  监督或评估标签；关键是未来真值和另一候选结果不能泄漏进在线特征，训练与
  评估必须独立划分。本预检尚未训练任何模型。
- 所有未经进度证书确认的终点都不能作为特征：需区分公开已授予的 MOVE 几何/
  cap 与未来真实到达状态，前者可以是合法已知信息，后者不能偷渡为已观测事实。

另作澄清：若改变观测时机后反转消失，这限制结果对其他协议的可迁移性，并不
推翻当前共同策略下的存在见证；同时说明收益属于几何、观测与准入规则的交互，
不能只归给误差幅值或模型。解析代价是必要对照，当前没有证据证明学习必需。
