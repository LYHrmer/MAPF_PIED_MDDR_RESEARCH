# R14 source, view and reuse schema

`REGISTRATION.json` binds every scientific source, twelve R13 checkpoint/public input pairs, all prior author replies/receipts needed by the caches, binary, author source archive, adapter and exact GSES config before any R14 view is generated. Labels in paths remain provenance; the solver receives only `solver_graph`.

`public/{context}.json` is `public_base`: unchanged R13 fields plus `schema` and `observed_events`. Event whitelist is frozen in `bridge.KINDS`; no HALF_END pause, heap, private segments or profile. `arrived_states` and `solver_graph.current` are actual completed ARRIVE states, not position estimates. Each active commitment gives agent, from/to state, origin and destination.

`evidence/{context}.json` has request, body, receipt and trusted_receipt_sha256. Domain is `r14_affine_simulated_position_v1`. The source is `synthetic_position_measurement`; production_cost is null. Request binds public-base digest, current time, chosen agent/occurrence/geometry and MOVE_START. Body supplies exact rational position and equal lower/upper progress bounds at the same captured/delivered time. It has no velocity, ETA, future pause or ARRIVE bit. Receipt binds original checkpoint, request and body. The measurement issuer may read private affine segments to calculate that one current point; consumer sees only the restricted issued message and trusted local receipt. This is a simulation trust boundary, not a production signature or adversarial issuer proof. Actual main guest certificate bodies belong to a different domain and must be rejected here.

`views/{context}__public.json` and `__position.json` include public/evidence digests, weighted solver_graph and all active MOVE estimate rows. Each row gives public interval/landmark/elapsed, public and used alpha, estimated residual, integer weight and estimate_source. Position changes at most one preselected row. Current type1 uses max(1,ceil(residual)); non-active R13 weights and all future1 remain. Private snapshots stay outside these files.

`VIEWS.json` records all requested keys before solving, their canonical identities and users, old successful references and the complete new-key set. `OLD_SOLVER_CACHE.json` retains every old GSES receipt, including duplicate keys; disagreeing selected graphs would be disclosed and earliest successful receipt would win. This run had none.

A solver key includes canonical graph SHA, method, config, executable, adapter, source-binding and upstream archive hashes. A new `calls/{key}/FIRST_ATTEMPT.json` is written before process launch; input, stdout/stderr, author_reply and receipt stay at that key. Existing successful receipts are reused; incomplete folders stop execution, not silently rerun. Failed completed attempts are preserved and are not retried automatically.

`RESULTS.json` has 36 rows: context × keep/public/position. It includes all requested audit fields: solver_key, call_source and receipt reference; checkpoint SHA; public_base/search_view/evidence paths and hashes; candidate/adopted graph hashes; actual guard metadata; continuation_key and continuation_source. `guards/{context}__{option}.json` includes the actual full execution graph. Candidate type1 is verified against search view, then search-only weights are removed before the unchanged R13 guard/lift. Type2 family membership and active/complete/satisfied dependencies are preserved.

Continuation key binds packed full checkpoint SHA, adopted full execution graph, executor/guard source hashes and semantics. `continuation_source` explicitly says reused_R13/reused_R14/new, gives original raw path and packed/raw hashes, original completion sum and makespan. Here all 36 are reused_R13 and no new raw trajectory is generated. Matching only public graph is insufficient: different hidden profiles/checkpoints cannot share this key. Reused original/GSES/Improved traces are eligible only under the exact key; this is no new Improved solver invocation.

`SENSITIVITY.csv` traces selected alpha → residual → ceil weight → adopted graph → outcome, including zero changes. `RESUME_CHECK.json` proves second orchestration left call artifacts and RESULTS byte-identical, with zero new calls/continuations. `REUSED_MEMBERS.json` names frozen external R13 dependencies; they are not counted as newly generated members. The future publication manifest covers new package files separately.
