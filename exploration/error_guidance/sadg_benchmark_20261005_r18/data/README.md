# R18 standard-map initial path data

The complete registered matrix contains **45 original ECBS attempts, all independently discrete-valid**. There were zero timeouts, zero retries, and zero substitutions. This is initial-path feasibility, not evidence about continuous execution or query-policy performance.

Read `CASES.json` for the complete index. Each row has `case_id`, `family`, `map_name`, `scenario_id`, `num_agents`, `split`, `status`, and absolute `case_path`, `validation_path`, and `receipt_path`. The canonical portable location is `cases/<case_id>/plan.json`; reconstruct it relative to this directory after moving the bundle. The index retains every registered row, including failures if any (none occurred).

Each plan provides:

```json
{
  "case_id": "random-32-32-10__s01__n08",
  "family": "random",
  "map_name": "random-32-32-10",
  "scenario_id": 1,
  "split": "train",
  "num_agents": 8,
  "status": "valid",
  "solution": {"schedule": {"agent0": [{"x": 0, "y": 0, "t": 0}]}},
  "dimensions": {"dimensions": {"resolution": 2, "x_offset": 0, "y_offset": 0}},
  "provenance": {}
}
```

The example state above illustrates the schema only; use the actual full paths. `solution` also retains the original planner statistics. Coordinates are MovingAI grid columns (`x`) and rows (`y`), with integer steps. The unchanged author SADG parser maps these into world coordinates `(2*y,-2*x)`. That rotation/reflection and scale must be used consistently for geometry; this dataset is not the live PIE position-evidence domain.

`family` is a display category (`random`, `maze`, `warehouse`). It is **not an independent statistical unit**. A matched scenario block is `(map_name, scenario_id)`; 8/16/32-agent instances use nested prefixes within that block. Parent execution experiments may add disturbances to the same block but must not count them as independent map draws. Scenario indices are official file indices, not new random seeds generated by this script. Training uses IDs 1/2, calibration uses 3, and test uses 4/5. This is a held-out-scenario split on the same three maps, not held-out-map generalization.

Official sources were downloaded before solving and are retained byte-for-byte with response metadata and SHA-256 hashes in `DOWNLOAD_RECEIPTS.json`. The [official MAPF index](https://movingai.com/benchmarks/mapf/index.html) links all six archives:

| Map | Map archive | Official random scenarios |
|---|---|---|
| random-32-32-10, 32×32 | [map](https://movingai.com/benchmarks/mapf/random-32-32-10.map.zip) | [scenarios](https://movingai.com/benchmarks/mapf/random-32-32-10.map-scen-random.zip) |
| maze-32-32-2, 32×32 | [map](https://movingai.com/benchmarks/mapf/maze-32-32-2.map.zip) | [scenarios](https://movingai.com/benchmarks/mapf/maze-32-32-2.map-scen-random.zip) |
| warehouse-10-20-10-2-1, 161×63 | [map](https://movingai.com/benchmarks/mapf/warehouse-10-20-10-2-1.map.zip) | [scenarios](https://movingai.com/benchmarks/mapf/warehouse-10-20-10-2-1.map-scen-random.zip) |

Only scenario files 1–5 are extracted into `sources/`; full original scenario archives remain in `downloads/`. The [official format description](https://movingai.com/benchmarks/formats.html) defines `.` as passable and `T`/`@` as blocked. These are the only characters in the selected maps. Scenario distance fields are not used as four-connected costs. No specific redistribution license for the benchmark data was established from these pages; do not label the maps CC/MIT/AGPL by inference. Preserve attribution and verify applicable benchmark terms before public redistribution. Author software licenses remain in the two source archives; they do not license the maps.

The existing random map and scenario 1/2 copies were hash-matched against the new official downloads (`LOCAL_INPUT_REUSE_AUDIT.json`). Existing R16 ECBS solved a different four-agent fixture; published GSES/PBS paths use different agent counts and another planner. No identical previous ECBS path set was found. The already-built author executable was reused without rebuilding.

`AUTHOR_PIN.json` records clean tracked-source hashes, source archive hashes, and binary pin:

- SADG controller: `c2626d996121a9d6c128844a167b917db24418ac`.
- Its libMultiRobotPlanning submodule: `4c75fa20c435c440d8b6bd6dc81668ddc7296ba0`.
- ECBS binary SHA-256: `ca8f0e10f73f831ff18d1d3c4382e2f2c87aad409f3fafb523bffad309f5062f`.

All 45 runs used unchanged ECBS with `-w 1.5`, default goal holding, one worker, 30-second wall limit, and a 4-GiB address-space cap. R16's different fixture used `-w 1.0`; that setting was not silently carried into this batch. The matrix was registered before the first solve (`REGISTERED_MATRIX.json`, SHA-256 `81cc37c5b05f5a9d8830c1cfefeb7ab0a4548173c370f1ef45aea5033097d3b8`). The wall times measure wrapper-inclusive attempts on this machine; they are not comparative planner timing results.

`validate_paths.py` is independent of the planner implementation. It reads official map/scenario files and checks agent identities, integer contiguous time, start/goal, map bounds, obstacles, legal four-connected moves/waits, vertex conflicts, swaps, and goal holding. It explicitly extends short paths to the joint horizon plus one. Distinct stationary final goals then establish the infinite goal-hold suffix. `audit_dataset.py` additionally checks YAML-to-official-input agreement, every result against raw YAML and hashes, registration timestamps, unchanged source/binary hashes, and ten synthetic validator challenges. `VALIDATION_AUDIT.json` records all checks passing.
