# Published guidance comparator, R4

Frozen before build and evaluation. This is a baseline reproduction extension, not a new method.

Compare the previously frozen R3 trained OnlineGGO checkpoint and all-5 initialization with **hm+GPIBT**, using the OnlineGGO authors' unchanged native implementation of SUM_OVC (`OBJECTIVE=3`). The R3 learned implementation uses `OBJECTIVE=4`. Keep swap, guidance and initial prioritized planning enabled; disable guidance LNS, flow guidance and focal search exactly as in the R3 build. This corresponds to the named human-designed comparator in Online Guidance Graph Optimization for Lifelong Multi-Agent Path Finding, AAAI 2025, section 4.1: https://ojs.aaai.org/index.php/AAAI/article/download/33614/35769 . Do not substitute the separately configured standalone GPIBT executable.

Use the author's sortation_small Kiva map and kwargs, 800 agents, 1000 simulation steps, three previously declared holdout seeds 930101, 930103, 930107. Run hm+GPIBT once per seed, sequential fresh processes, with 120 s limit each. Reuse the six frozen R3 learned/initial runs and their full traces; do not retrain, select another checkpoint, tune parameters, or rerun unfavorable outcomes. Compare completed tasks and throughput. Three seeds on one map are a screening experiment, not the paper's 50-run benchmark or a statistical superiority claim. All failures are retained.

Task generation: Kiva's W/E task sampling consumes a shared generator in completion-dependent order. Equal seeds preserve the author's task-generation law and initial conditions, but do NOT guarantee identical future task assignments per agent. Priority tie randomness also prevents a fully paired experiment. Audit initial starts/assignments and report later assignment agreement explicitly. No execution error is injected; this comparator does not by itself validate the error-aware research method.

Run the frozen R3 independent verifier on all three new full native trajectories (2.4 million actions): boundaries, obstacles, vertex/edge conflicts, FIFO task events, actual goal arrival, throughput. Verify all upstream tracked Git blobs before and after compilation/runs, record build commands, flags, native module hash, stdout/stderr, job arguments and results. Preserve all native traces in an archive with per-file hashes. Runtime fields are descriptive, not a performance comparison (R3 and R4 concurrency differ).
