# SCI MAPF 支线

本线问题是：**给定合法的多机器人路径方案，如何在有限总计算预算内进一步改善路径质量？** 目标是在2026年形成SCI稿件；当前为候选问题验证阶段，尚无独立算法优势。唯一总体决定在[main](https://github.com/LYHrmer/MAPF_PIED_MDDR_RESEARCH/blob/main/docs/RESEARCH_PLAN.md)，本页只维护本线入口。

## 实现主干与当前工作

以**ADDRESS**为实现主干，复用其邻域生成、在线种子选择和完整修复循环。BALANCE提供轻量在线资源选择参考，TACKLE用于比较学习选种子机制，确需神经表示时再考虑NNS；不另搭深度RL系统，不恢复L20/L21或旧查询学习。

- [address_backend.py](address_backend.py)：已实现共同宿主的合法性证明复用。不变路径子集可复用检查，新增路径仍检查顶点、对向边与永久终点驻留；接纳和最终输出保留完整校验。按任务/模型/车辆/不可变路径身份绑定，失败与回滚不能继承不适用证明。
- [pp_repair.py](pp_repair.py)与[run_repair_dev.py](run_repair_dev.py)：完整修复事务、同一绝对截止和失败账本。新增`host_callback_costs`区分验证、哈希、RPC编码/传输/解码；父子区间嵌套，不重复加入总成本。RPC包含通信和作者计算，不等于纯搜索时间。
- [完整ADDRESS适配](ADDRESS_ADAPTER.md)：共同初解、显式随机源、作者推荐配置、原奖励/回滚语义及完整预算接口。原作者缓存只读；改动仅生成到小型构建overlay，原版与适配版分开记录。实现/编译/软件核验与科学运行状态分别见该报告。
- [后段失败诊断与候选规则](LATE_FAILURE_DIAGNOSIS.md)：只解析固定DEV记录，先确定失败位置和限制线索，再考虑有限局部恢复。回退本身不是创新；尚未执行恢复比较。
- [原生恢复扩展](ADDRESS_RECOVERY.md)：abandon/random/anchor使用主修复同一wall/CPU截止；诊断、私有占用表、全检和提交均受同一预算约束。私有完整候选通过后交换提交，到期撤销并走原rollback。运行器尚不接受恢复变体；后续真实记录未观察到原门槛内的触发机会，当前材料上的候选已停止，收益没有比较。

共同宿主优化用于Python固定请求探针，尚未测得真实性能提升；冷缓存增量检查也可能产生额外开销。原生完整ADDRESS没有逐次Python RPC检查，不能把两种架构的费用差额写成方法加速。后继候选与ADDRESS应共用同一完整框架、初末校验与缓存条件；固定ID组探针不冒充其自适应循环。

## 模型、依赖和费用

共同模型为四邻域、单位离散步、等待、顶点/对向边冲突及永久终点驻留。SOC不是物理秒，离散合法不证明连续车身安全。下界/cap只约束当前顺序及前缀；有限cap正常穷尽不代表所有顺序或整个MAPF问题无解。

原生后端构造、真实SIPP与完整ADDRESS实例调用都属科学运行。导入、静态检查、假回调测试、编译及help不运行科学任务。总费用覆盖输入检查、构造、缓存、求解、恢复、末检与写盘；父收据自身写盘的计时边界单列。失败不删，不能只报求解内层耗时。

## 下一项与停止条件

后段恢复候选保持停止。[非修复费用核查](ADDRESS_NONREPAIR.md)已定位一个具体机制：random32仅车辆19有延迟，其他31车无法启动严格改善游走，却仍参与抽样且构组失败不更新Beta；这是旧路径与源码推导，尚无新种子日志或耗时分账。共同预算还可能触发大量clock读取，不能把残差全归作者算法。可选独占计时、种子/构组计数和预算检查采样已实现并完成软件核验及编译；[两项计时诊断清单](ADDRESS_PHASE_CHECKLIST.md)待新授权。先定位主费用，再在共同工程优化、简单必要条件准入之后选择一个明确增量，不直接训练或恢复旧候选。

学习按真实决策需要选择监督、在线学习或RL；三个正例不构成训练依据。算法在本线维护一份，硕士通过固定提交引用。历史详细实现说明见[535ee1a版本](https://github.com/LYHrmer/MAPF_PIED_MDDR_RESEARCH/blob/535ee1adf3135ab79565e0b3aa5d189348fe7ab2/tracks/sci/README.md)，其中旧待运行表述不再是当前状态。
